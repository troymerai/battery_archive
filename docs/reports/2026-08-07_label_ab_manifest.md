바뀌는 것은 그 목록 중 **몇 셀이 살아남느냐**입니다.

| | train | val | test |
|---|---:|---:|---:|
| 목록 (841 판) | 510 | 165 | 162 |
| A 로 살아남는 셀 | 503 | 162 | **158** |
| B 로 살아남는 셀 | 441 | 143 | 140 |
| **Tongji 키 문제를 풀었다면** | **503** | **162** | **158** |

### 시험 집합 162셀 중 라벨이 바뀌는 셀

| 항목 | 값 |
|---|---:|
| 라벨 값이 바뀌는 셀 | **27** |
| 그중 ISU-ILCC | **27 (전부)** |
| Tongji (값은 1 사이클 차, 키 때문에 조회 실패) | 21 |
| 값도 조회도 그대로인 셀 | 114 |

`[확인]` 시험 집합에서 **ISU-ILCC 27셀의 정답이 달라집니다.** 실제 평가되는
158셀 기준으로 **17.1%** 입니다. 이 셀들은 규칙 5 를 넘나들지 않으므로
**표본에는 남고 정답만 바뀝니다** — A/B 비교에 정확히 필요한 성질입니다.

## 5. 추론 하네스 A/B 대응 상태 (§3)

### 5-1. 라벨 경로는 하드코딩이었고, 인자로 바꿨습니다

`[확인]` 상위는 `{root_path}/Life labels/{prefix}_labels.json` 을 직접
엽니다 (`data_loader.py:417-431`). `train/infer_cell_preds.py` 에
`--labels {A,B}` 를 더했습니다.

* `A` = `data/extracted/Life labels` (배포판)
* `B` = `data/labels_B` (재생성)

산출물은 **자동으로 갈립니다** — B 조건은 `cell_metrics_B.json` ·
`<조합>_B.npz` 로 나갑니다. 두 조건이 같은 파일을 덮어써서 실험이 조용히
무너지는 일을 막습니다 (`cell_predictions` §10-5 가 미정으로 둔 항목).

### 5-2. 도중에 잡은 함정 — 캐시가 라벨을 덮어씁니다

`[확인]` **처음 붙였을 때 `--labels B` 가 아무 효과가 없었습니다.**
`라벨 {'found': 0, ...}` 로 조회가 한 번도 일어나지 않았습니다.

원인: **입력 텐서 캐시 색인이 `eol` 을 함께 담고 있습니다.**
캐시 패치는 `read_cell_df` 를 통째로 대체하므로
`read_cell_data_according_to_prefix` 를 아예 부르지 않고, **캐시를 만든
시점의 A 라벨이 그대로 쓰입니다.**

이대로 A/B 학습을 돌렸다면 **두 조건이 똑같은 라벨로 돌면서 "차이 없음"이라는
결론이 나왔을 것입니다.** 지시가 3번을 요구한 것이 정확했습니다.

고친 방식: `install_tensor_cache(..., eol_lookup=...)` 를 더해 **`eol` 만
라벨 원본에서 받아오고** 입력 텐서와 `valid_cycle_number` 는 캐시 값을
그대로 씁니다. 입력을 공유한다는 캐시의 취지가 유지됩니다 `[확인]`.

### 5-3. B 로는 Li-ion 이 **돌지 않습니다** — 그대로 드러냅니다

`[확인]` §3-4 의 키 문제 때문에 Tongji 조회가 실패하고, 상위가 그 자리에서
죽습니다.

```
ValueError: not enough values to unpack (expected 6, got 5)
  data_loader.py:487 (read_samples_from_one_cell)
```

상위 잠복 결함입니다 — `read_cell_df` 는 라벨이 없으면 **5-튜플**을
돌려주는데(`:443`) 호출부는 **6개**를 풉니다. 라벨 A 에서는 `.build` 진입점이
문제 셀 6개를 미리 빼기 때문에 드러나지 않았습니다 (TRN-010).

**조용히 그 셀을 건너뛰지 않았습니다** — 건너뛰면 표본이 바뀝니다. 대신
`LabelMissing` 예외로 **어느 셀에서 걸렸는지 짚고 그 조합을 통째로
버립니다.**

```
[1/1] CPMLP_Li-ion_s2021   **라벨없음으로 중단**
      'Tongji1_CY45-05_1--2.pkl' 의 수명 라벨을 data\labels_B 에서 찾지 못했습니다.
      상위 read_samples_from_one_cell(data_loader.py:487) 이 5-튜플을 6개로 풀려다 죽는 자리입니다.
      건너뛰면 표본이 바뀝니다 — 조용히 넘기지 않습니다.
```

### 5-4. 양성 대조 — Zn-ion 에서는 B 가 제대로 돕니다

`[확인]` ZN-coin 은 A 와 B 의 라벨이 121셀 전부 같습니다. 그러니 A 로 돌린
결과와 B 로 돌린 결과가 **바이트 단위로 같아야** 하고, 실제로 같습니다.

```
CPMLP_Zn-ion_s2021  --labels B  → 라벨 {'found': 20, 'missing': 0, 'no_file': 0}
preds / refs / seen_unseen_id / dataset_id / cell_start / cell_stop / cell_files
  A 대비 전부 동일: True
```

라벨 교체 경로가 **실제로 동작하면서**(found 20) 결과가 같다는 것이므로,
§5-2 의 함정이 제대로 막혔다는 증거입니다.

### 5-5. 셀 경계를 미리 계산한 표에서 읽지 않게 바꿨습니다

`[확인]` 기존 하네스는 `cell_sample_counts.json`(A 라벨 기준)에서 경계를
읽었습니다. 라벨이 바뀌면 그 표가 틀립니다. `install_cell_recorder` 로
**데이터셋을 지으면서 셀마다 몇 샘플이 나오는지 그 자리에서 관측**하도록
바꿨습니다. A 일 때는 기존 표와 대조까지 합니다 (교차 검증, 통과).

## 9. 지시에 없던 판단이 필요했던 사항

1. **`pyarrow` 실패를 "재현 불가"로 부풀리지 않았습니다.** 첫 19/19 실패는
   사실이지만, `datasets==2.19.0` 이 `pyarrow` 를 전이로 끌어오므로
   `requirements.txt` 를 온전히 설치한 사람은 겪지 않습니다. **직접 의존
   미선언이라는 취약성으로만** 적었습니다. 더 무겁게 볼 근거가 있으면
   알려 주십시오.

2. **`ISU-ILCC_labels.json` 을 손으로 복사했습니다.** 스크립트는 밑줄판
   `ISU_ILCC_labels.json` 을 내놓는데 로더는 붙임표를 읽습니다(§3-4 와 같은
   종류의 결함). 지시가 "학습 코드가 A 를 읽는 방식 그대로 B 를 읽을 수
   있어야 한다"고 해서 **파일 이름만** 복사했습니다. 내용은 손대지 않았고,
   **원본 출력도 지우지 않았습니다.** `data/labels_B/README.md` 에 적었습니다.

3. **Tongji 키(`--` vs `-#`)는 고치지 않았습니다.** 고치면 라벨 내용을
   손대는 것이고 규칙 4 위반입니다. 그 결과 **B 로는 Li-ion 이 아예 돌지
   않습니다**(§5-3). 학습 설계상 셋 중 하나를 정해 주셔야 합니다 —
   (가) 키를 맞춘 B′ 를 따로 만들어 쓰고 그 사실을 논문에 적는다,
   (나) Tongji 를 뺀 부분집합으로 A/B 를 돈다,
   (다) "공개 코드로는 학습 자체가 불가능하다"를 결과로 삼는다.
   **(다)가 실험이 묻는 질문에 가장 곧은 답으로 보입니다만 정하지
   않았습니다.**

4. **`entrypoint.py`(학습 경로)에 라벨 교체를 넣지 않았습니다.** §5-2 의
   함정이 **학습 경로에도 그대로 있습니다** — `BLIFE_TENSOR_CACHE` 를 켜고
   A/B 학습을 돌리면 두 조건이 같은 라벨로 돕니다. 공용 모듈에 기능은
   넣었으니 진입점에 `BLIFE_LABELS` 를 세 줄로 붙일 수 있지만, 지시가
   "학습으로 넘어가지 않는다"고 해서 **멈췄습니다. 이건 지뢰라 먼저
   처리하시길 권합니다.**

5. **`MIX_large_841` 셀 목록 중복을 남겼습니다.** §6 의 이유입니다.
   합치면 진입점의 추가 검사를 옮겨야 해서 지시 범위를 넘습니다.

6. **CALB 를 "생성 불가"로 두고 우회하지 않았습니다.** 지시대로입니다.
   그 결과 **CALB 도메인은 A/B 실험을 할 수 없습니다.** Li-ion 이 주 대상이라
   범위 밖으로 보았습니다.

7. **매니페스트를 두 시선으로 냈습니다.** 로더 시선(규칙 5 판정의 정본)과
   파일 시선(값 비교). 하나로 합치면 Tongji 키 문제가 값 차이에 섞여 보이지
   않게 됩니다. 지시에 없는 구성이지만 이렇게 하지 않으면 §1-2 의 결론이
   나오지 않습니다.
