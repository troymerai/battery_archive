## 0. 왜 이걸 적는가

이 저장소의 존재 이유는 출처 추적이고, `LOCK.md` 는 "모두가 같은 것을 본다" 의
계약서다(README). 계약이 깨져 있던 사실 자체를 기록하지 않으면, 나중에 이

**깨졌던 사실과 기간을 스스로 적어두는 편이 나중에 발견되는 것보다 낫다.**

발견 경위: 2026-08-07 워킹 트리 정리 중 `DAT-004` 를 등록하기 전에 잠금 상태를
점검하다 나왔다. 정리 작업이 만든 문제가 아니라 **이미 있던 것을 찾은 것이다.**

## 1. 측정 방법 `[확인]`

해시는 저장소 자신의 함수를 썼다 — `verify/__init__.py:146` 의 `sha256_file()`
이다. 이 함수는 텍스트를 UTF-8 로 디코드한 뒤 정규화해서 sha256 을 낸다.
**`sha256sum` 을 그대로 쓰면 값이 다르게 나온다** — 줄바꿈 정규화 때문이다.
각 커밋 시점 값은 `git show <커밋>:findings/registry.yaml` 을 같은 함수에
통과시켜 얻었다. `LOCK.md` 기록값은 각 커밋 시점의 `LOCK.md` 에서 정규식으로
뽑았다.

## 5. 이 사실이 무효화하는 것 / 하지 않는 것

**무효화하지 않는 것.** 그 기간의 *데이터* 잠금(zip 20개 md5)과 *환경* 잠금은
별개 항목이고 이 조사에서 어긋난 증거를 찾지 못했다 `[미확인 — 이번에 재지 않았다]`.
학습 결과 36회의 숫자도 registry 와 무관하다.

**무효화하는 것.** 이 기간에 `python run.py check` 를 돌린 사람은 **CODE 층
불일치를 봤어야 한다.** 통과했다고 기억한다면 그 기억이 틀렸거나 `check` 를
돌리지 않은 것이다. 그리고 이 기간의 어떤 태그도 "registry 가 이 내용이었음" 을
보증하지 못한다.

## 6. 복구 — **`lock-init` 으로는 안 된다** `[확인]`

이 보고를 지시한 문서는 `run.py lock-init` 으로 복구하라고 적었다.
**코드를 읽어보니 그 명령은 이 문제를 고치지 못한다.**

`verify/lock.py:333-335`:

```python
expected = match.group("expected").strip()
if expected != UNSET:          # UNSET == "(미정)"
    out_lines.append(line)
    continue                    # 값이 있으면 건드리지 않고 넘어간다
```

같은 함수의 docstring 이 이유를 적는다 — **"이미 값이 들어 있는 행은 건드리지
않습니다. 기준값을 덮어쓰면 '모두가 같은 것을 본다' 가 무너집니다. 값을 바꿔야
한다면 새 태그를 찍으십시오."**

그리고 **`LOCK.md` 표 42행에 `(미정)` 이 하나도 없다** `[확인]`
(`grep "(미정)" LOCK.md` 의 3건은 전부 표 밖 설명문이다).

따라서 지금 `lock-init` 을 돌리면:

| | |
|---|---|
| 채우는 행 | **0개** |
| 고쳐지는 FAIL | **0건** |
| 실제로 일어나는 일 | `manifests/env_lock/repro.txt` 를 현재 인터프리터의 `pip freeze` 로 **덮어씀** (`verify/lock.py:316-319`) |

**즉 효과는 없고 부작용만 있다.** 게다가 그 부작용이 바로 README 가 경고한
그것이라, 잘못된 인터프리터로 부르면 지금 통과하고 있는 `env repro` 까지
깨진다.

### 그래서 복구는 사람이 정할 일이다

기준값을 바꾸는 것은 **계약을 바꾸는 것**이고, 이 모듈은 그것을 의도적으로
자동화하지 않았다. 세 FAIL 은 성격이 달라 한 번에 처리해서도 안 된다.

| FAIL | 올바른 처리 | 자동화 가능? |
|---|---|---|
| `upstream/BatteryML tree` | `*.egg-info` 를 잠금 대상에서 빼는 것이 맞다 (§4-1) | 아니오 — `verify/` 수정이 필요 |
| `verify/ tree` | 새 기준값으로 갱신 + 새 태그 | 아니오 — 사람의 결정 |
| `findings/registry.yaml` | 새 기준값으로 갱신 + 새 태그 | 아니오 — 사람의 결정 |

실행 결과 전문은 `docs/reports/2026-08-07_repo_cleanup.md` §8 에 있다.

## 7. 재발 방지 — 제안이며 이번에 구현하지 않았다

`registry.yaml` 은 `run.py claims` 로 자주 바뀌는 파일인데 digest 로 잠겨 있어

**이번 지시 범위 밖이라 하지 않았다.** 사람이 판단할 항목으로 올린다.
