## 1. 체크포인트 경로 분리

### 왜 갈라야 하는가

`[확인]` 네 조건(AA·AB·BA·BB)은 모델·하이퍼파라미터·시드가 같아 상위
`setting` 문자열이 **완전히 같습니다** — `run_main.py:141-151` 은 라벨을
문자열에 넣지 않습니다. 그런데 상위는 실행을 시작할 때 그 폴더를 **지웁니다**.

```python
213    if accelerator.is_local_main_process and os.path.exists(path):
214        del_files(path)  # delete checkpoint files
```

한 루트에 몰면 **뒤 조건이 앞 조건을 지웁니다.**

### 어떻게 갈랐는가

```
data/checkpoints_label_ab/AA/
data/checkpoints_label_ab/AB/
data/checkpoints_label_ab/BA/
data/checkpoints_label_ab/BB/
```

`setting` 에 접미사를 붙이는 대신 **루트를 갈랐습니다.** 접미사를 붙이려면
상위 문자열 생성부를 고쳐야 하는데 `upstream/` 은 금지입니다. 루트는
`--checkpoints` 인자로 밖에서 정할 수 있습니다 `[확인]`.

### 기존 684 MB 를 건드리지 않는지

`[확인]` 루트 자체가 다릅니다 — `data/checkpoints/` 와
`data/checkpoints_label_ab/` 는 형제입니다. 상위가 지우는 것은
`{checkpoints}/{setting}-{comment}` 하나뿐이라, 다른 루트를 주면 기존 트리에
닿을 수 없습니다.

러너가 시작할 때 **그 사실을 직접 확인합니다.**

```powershell
if ($newCkpt.StartsWith($oldCkpt + [IO.Path]::DirectorySeparatorChar)) {
    throw "체크포인트 경로가 기존 트리 안입니다. 갈라야 합니다: $newCkpt"
}
```

dry-run 로그에 실측이 찍힙니다 `[확인]`.

```
기존 체크포인트 683 MB — 이 러너는 checkpoints_label_ab 만 씁니다
```

작업 전후 `data/checkpoints/` 는 **684 MB · 46개 그대로**입니다 `[확인]`.

## 2. 조건 정의 — val 을 어디에 붙였는가

`[확인]` 조건 이름의 **앞 글자가 학습, 뒷 글자가 시험** 라벨입니다.

| 조건 | train | **val** | test |
|---|---|---|---|
| AA | A | **A** | A |
| AB | A | **A** | B |
| BA | B | **B** | A |
| BB | B | **B** | B |

> **val 은 train 을 따릅니다.** 지시에 없던 판단이라 §7-2 에 올립니다.
> 검증 집합은 조기종료와 최적 모델 선택에 쓰이므로 **학습 절차의 일부**입니다.
> val 에 시험 라벨을 주면 시험 정답이 모델 선택에 새어 듭니다.

이 규칙은 `BLIFE_LABELS` 문자열에 **명시적으로** 적힙니다
(`train=A,val=A,test=B`). 로그만 보고도 조건을 읽을 수 있습니다 `[확인]`.

## 3. 진입점 — 분할별 라벨 지원 추가

0단계의 `BLIFE_LABELS` 는 **전 분할에 하나의 라벨**만 줄 수 있었습니다.
AB·BA 조건은 그걸로 표현되지 않습니다 `[확인]`.

그래서 `train/blife_patches.py` 의 `make_eol_lookup` · `install_label_source`
를 **`{flag: 경로}` 를 받도록** 고쳤습니다. 분할은 `self.flag` 로 가릅니다 —
`data_loader.py:100` 에서 `read_data()`(`:229`)보다 먼저 정해지므로 조회
시점에 이미 알 수 있습니다 `[확인]`.

진입점은 두 형식을 다 받습니다.

| `BLIFE_LABELS` | 뜻 |
|---|---|
| `A` · `B` · 경로 | 전 분할 공통 (0단계와 같음) |
| `train=A,val=A,test=B` | **분할마다 다른 라벨** |

동작 확인 `[확인]` — `ISU-ILCC_G34C2.pkl` 은 A 가 3109, B 가 317 입니다.

```
train flag: 3109      <- A 라벨
test  flag: 317       <- B 라벨
by_flag: {'train': 'data/extracted/Life labels', 'test': 'data/labels_B'}
```

`.build` 재생성 뒤 템플릿과의 차이는 **`@@RUN_MAIN@@` 치환 2곳뿐**입니다
`[확인]`.

## 7. 지시에 없던 판단이 필요했던 사항

### 7-1. **학습을 한 번 실수로 시작했습니다** — 그대로 적습니다

재개 로직을 확인하려고 러너를 불렀는데 **`-DryRun` 을 빠뜨렸습니다.**
`AA/CPMLP/s42` 는 미리 놓은 결과 파일 때문에 건너뛰었고,
**`AB/CPMLP/s42` 학습이 실제로 시작됐습니다.** 알아차리고 **즉시
죽였습니다** `[확인]`.

| 남은 것 | 처리 |
|---|---|
| `data/checkpoints_label_ab/AB/` (1.8 MB, 미완성) | **삭제** `[확인]` |
| `runs/label_ab/_progress.log` | **삭제** `[확인]` |
| 결과 JSON | **생성되지 않음** — 학습이 끝나야 씁니다 `[확인]` |
| `data/checkpoints/` 684 MB | **무사** — 루트가 달라 닿지 않았습니다 `[확인]` |

작업 후 `experiments/results/label_ab/` 아래 **파일이 하나도 없습니다**
`[확인]`. 저장소는 "학습을 돌리지 않은" 상태와 같습니다. `curves/` 58건도
그대로입니다 `[확인]`.

이후 재개 검증은 러너를 부르지 않고 **판정식만 따로 평가**했습니다 (§5-4).

### 7-2. val 을 train 조건에 붙였습니다

§2 의 이유입니다. **AB 는 "학습 A, 시험 B"이지 "학습 A, 검증 B, 시험 B"가
아닙니다.** 다르게 보신다면 `BLIFE_LABELS` 의 `val=` 만 바꾸면 됩니다 —
진입점이 셋을 따로 받습니다.

### 7-3. 체크포인트를 `setting` 접미사가 아니라 **루트 분리**로 갈랐습니다

접미사는 상위 문자열 생성부를 고쳐야 해서 `upstream/` 금지에 걸립니다.

### 7-4. `blife_patches.py` 를 한 번 망가뜨렸다가 복구했습니다

분할별 라벨을 넣다가 일괄 치환을 잘못 걸어 파일이 34만 줄로 불어났습니다.
`git checkout` 으로 HEAD(커밋 `b233384`) 판을 되살린 뒤, 0단계에서 넣었던
`apply_exclude_prefixes` 와 이번 분할별 라벨을 **하나씩 다시** 넣었습니다.
현재 320줄이고 구문·임포트·조회 동작을 확인했습니다 `[확인]`.

`[미확인]` 0단계에서 학습으로 검증한 동작(캐시·제외·라벨 교체)이 그대로인지는
**§3 의 조회 확인과 dry-run 까지만** 확인했습니다. 학습으로 재확인하지
않았습니다 — §8 의 첫 조합에서 함께 드러납니다.

### 7-5. 40회 예상 시간을 다시 계산하지 않았습니다

0단계 §6 의 추정(CPMLP 7.8분 · CPTransformer 20.3분 → 40회 약 9.4시간)이
그대로입니다. 이번에 학습을 돌리지 않았으므로 새 측정치가 없습니다.
