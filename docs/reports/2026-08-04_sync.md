### 불일치 3행 — 왜 어긋났는가

**어느 것도 데이터·결과가 달라진 것이 아닙니다.** 셋 다 *잠금 기준값이
갱신되지 않은 것* 입니다 — 이 작업이 닫으려던 그 문제가 `LOCK.md` 안에서
일어났습니다.

#### ① `upstream/BatteryML tree`

```
기준 7368a9cd…03c8bca4      실제 e1e948ca…be288621
```

**원인은 `pip install -e` 가 `upstream/BatteryML/BatteryML.egg-info/` 를
만든 것입니다.** 파일 6개(`PKG-INFO` · `SOURCES.txt` · `requires.txt` ·
`top_level.txt` · `entry_points.txt` · `dependency_links.txt`)입니다.

**egg-info 를 빼고 다시 계산하면 기준값이 바이트 단위로 재현됩니다.**

```
egg-info 제외 → 7368a9cdc0c375bb7a9ec9a548a7118279a997e1a35e0c245283fa7003c8bca4  (= 기준값)
```

즉 **상위 소스는 한 글자도 달라지지 않았습니다.** 환경 구축이
`upstream/` 을 건드린 것이고, 이 저장소는 `upstream/` 을 읽기 전용으로
선언합니다. 지우지 않았습니다 — 편집설치의 메타데이터라 지우면 설치가
깨집니다.

### 왜 제가 고치지 않았는가

`verify/lock.py` 의 `init()` 은 **이미 값이 있는 행을 덮어쓰지 않습니다.**
주석이 이유를 적습니다 — *"기준값을 덮어쓰면 모두가 같은 것을 본다 가

### 8-3. `LAB-005` 의 `paper` 슬롯을 바꾸지 않았습니다 — 판단 필요

`확인` 으로 바꾸면 판정이 `코드전용` 에서 **`일치` 또는 `불일치` 로
자동으로 뒤집힙니다.** "BatteryLife 논문에 근거가 없다" 는 관찰이 사라지는
것이라 제가 정할 일이 아니라고 봤습니다.

**대신 `REP-002` 를 새로 만들어 판정이 나오게 했습니다** — 그 레코드의
질문은 "다른 논문에 공식화되어 있는가" 이고 판정은 **일치**입니다.

> **두 논문을 한 슬롯으로 볼 것인지 정해 주십시오.** 한 슬롯으로 보기로
> 하면 `LAB-005` 의 `paper.status` 를 `확인` 으로 바꾸고 `locus` 에
> `BatteryMFormer 논문 2.2절 식 (2)` 를 넣으면 됩니다. **`verdict` 는
> 건드리지 마십시오** — 슬롯만 고치면 재생성됩니다.

`[16, 32, 64, 128]` 로 읽히는데 `assets/Selected_hyperparameters.md` 는
`[8, 16, 32, 64, 128, 256]` 이라고 적습니다. **어긋나 보입니다.** 다만
