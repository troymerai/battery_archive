## 2. 우선순위 규칙

### 규칙

1. **조건을 줄이지 않는다.** 도메인·seed·에폭 수를 깎아 개수를 맞추지
   않습니다. 깎은 결과는 Table 3 과 나란히 놓을 수 없습니다.
2. **열을 완결시킨다.** 한 도메인의 3모델 × 3seed 9회를 끝내면 Table 3 의
   한 열을 통째로 채울 수 있습니다. 여러 열을 조금씩 채우면 어느 것도
   보고할 수 없습니다.
3. **작은 도메인부터.** 같은 시간에 완결되는 열이 더 많습니다.
4. **같은 도메인 안에서는 CPMLP → MLP → CPTransformer.** CyclePatch 대조
   (CPMLP 대 MLP) 가 먼저 서야 그 열의 핵심 주장이 확인됩니다.

### 순서

| 단계 | 내용 | 회수 | 이 단계 (100에폭 상한) | 누적 | **실측 (2026-08-04)** |
|---|---|---:|---|---|---|
| **A** | CALB 9회 | 9 | ~0.9시간 | ~0.9시간 | **7분 13초** (15:29:40 → 15:36:53) |
| **B** | Na-ion 9회 | 9 | ~1.0시간 | ~1.9시간 | **6분 29초** (15:36:53 → 15:43:22) |
| **C** | Zn-ion 9회 | 9 | ~3.3시간 | ~5.2시간 | **16분 54초** (15:43:22 → 16:00:16) |
| **D** | Li-ion 9회 | 9 | ~27.9시간 | ~33시간 | **3시간 17분** (17:22:14 → 20:39:27) |

**추정이 크게 빗나갔습니다.** A·B·C 27회는 5.2시간 추정에 **실측 30분 36초**
로 10분의 1 이고, D 도 27.9시간 추정에 3시간 17분입니다. 이유는 §3-3 이
**100에폭 상한**을 가정했기 때문입니다 — 실제로는 조기 종료(`patience=5`)가
훨씬 이르게 걸립니다. §3-5 가 "33시간과 11시간 사이 어디" 라고 적은 그
아래쪽 바깥입니다. 근거는 `runs/2026-08-04/*_summary.txt` 세 개(A·B·C)와
`run_liion.log` 의 torch 경고 타임스탬프(D)입니다.

D 의 3시간 17분에는 **회당 약 10분의 데이터 로딩이 9번** 들어 있습니다
(§3-0). 그것을 빼면 학습 자체는 2시간 안팎입니다.

A→B→C 만으로 **Table 3 의 4열 중 3열이 완결**되고 5시간 남짓입니다.
여기서 멈춰도 보고할 것이 있습니다. D 는 나머지 전부보다 5배 깁니다.

**D 의 선결 과제(TRN-010, 라벨 미배포 6셀)는 풀렸습니다.**
`--dataset MIX_large_841` 로 로딩이 끝까지 갑니다 (2026-08-04 실측 —
`docs/RUN.md` §8-5).

**대신 다른 것이 나왔습니다 — TRN-011.** `data_loader.py:234` 이 Li-ion
train 을 **33.7 GiB float64 배열 한 덩어리**로 만듭니다. 같은 명령이

A·B·C 세 열은 배열이 4 GiB 이하라 영향이 없습니다.

명령은 `docs/RUN.md` §3-2 의 `run_domain.sh` 한 줄입니다.

### 3-1. 3에폭 실측 (2026-08-04, **문서 하이퍼파라미터**)

`_timing36_*.sh` 둘. `train_epochs=3` 말고는 정식 파일과 같습니다.

- "에폭 평균" 은 로그의 `Epoch: N cost time` 세 개의 평균입니다 (학습 루프).
- VRAM 은 nvidia-smi 의 **GPU 전체 사용량**입니다. 유휴 시 958 MiB 가
  깔려 있으므로 순증분은 각각 약 0.4 / 0.6 GiB 입니다.
- **VRAM 한도(15,000 MiB)를 넘지 않았습니다. OOM 도 없었습니다.**

잔차(`wall − 로딩 − Σ에폭`)는 CPMLP 13.6초 · CPTransformer 11.8초입니다.
둘이 비슷하므로 대부분이 **모델과 무관한 고정 기동 시간**입니다 (torch
import · accelerate 기동). 아래 환산에서 **F = 12초**로 씁니다.

### 3-2. 환산식

```
한 회 소요 = F(12초) + 로딩(도메인) + 에폭수 × 에폭시간(모델) × 규모(도메인)

에폭시간(CPMLP)          = 2.1초    (측정 1.81 + 평가 여유)
에폭시간(CPTransformer)  = 6.1초    (측정 5.78 + 평가 여유)
에폭시간(MLP)            = 2.1초    ** 재지 않았습니다. CPMLP 값을 대입 **
규모(도메인)             = 샘플 합 / 2,683
```

## 5. `Transformer` 처리 — 두 갈래

논문 Table 3 은 `Transformer` 를 네 도메인 전부 `-` 로 적고, 캡션에서
`-` 를 out of memory 로 설명합니다.

**그러나 배포 코드에서는 메모리에 닿기 전에 죽습니다** (TRN-008).

```
models/Transformer.py:71   configs.num_class     ← 인자 이름이 없음
run_main.py:102            --class_num           ← 실제 인자 이름
→ Model(args) 생성 시점에 AttributeError. 2026-08-04 실측
```

추가로 `forward` 가 위치인자 4개를 요구하는데 `run_main.py:322` 는 2개만
넘기고, 배치가 `[B, 100, 300, 3]` 4차원인데 `DataEmbedding` 은 3차원을
가정합니다. 같은 조건에서 `MLP` · `CPMLP` · `CPTransformer` 는 셋 다
생성과 호출이 통과합니다.

| 갈래 | 실행 목록 | 뜻 |
|---|---|---|
| **제외** | 3종 × 4도메인 × 3회 = **36회** | 논문과 같은 결과(`-`). 다만 사유가 OOM 이 아니라 코드 결함이라는 것을 기록 |
| **포함** | 4종 × 4도메인 × 3회 = **48회** | OOM 재현 여부 자체를 검증 항목으로 삼음. **상위 코드를 고쳐야 하고, 고치는 순간 논문과 같은 조건이 아님** |

**권장은 "제외"입니다.** 포함하려면 `num_class` · `forward` 시그니처 ·
입력 차원 셋을 다 고쳐야 하는데, 그것은 재현이 아니라 이식입니다.
다만 **"논문의 `-` 는 OOM 이 아니라 실행 불가였다"** 는 관찰 자체가
보고 가치가 있습니다 — `findings` TRN-008 에 기록해 두었습니다.

현재 `.build/batterylife/Transformer_{CALB,MIX_large}.sh` 2개는
**돌리면 즉시 실패합니다.** 남겨 두되 실행 목록에서는 뺐습니다.

#### ① Zn-ion 은 학습률을 조정한 결과입니다 — 문서 조건이 아닙니다

#### ② Zn-ion 은 모집단이 다릅니다 — 직접 비교가 성립하지 않습니다

**논문 Table 2 의 Zn-ion 은 95셀이고 코드 분할은 100셀입니다.** v11 에서 이
서브셋의 라벨이 26셀 늘었습니다. 5셀 차이 중 1셀은 수명이 정확히 100 인
셀이 남아 있는 것으로 설명되고(부록 A.1 은 "100 이하 제외" 라고 적는데 분할은
100 미만만 뺐습니다 — `findings` LAB-018), **나머지 4셀은 설명되지 않습니다.**

Zn-ion 두 행은 **다른 셀 집합에서 잰 값을 나란히 놓은 것**입니다. ① 의
학습률 차이까지 겹치므로, 이 열의 숫자가 가깝다는 것을 재현의 근거로 쓰지
마십시오.

#### ③ 판정 기준 — 구간 겹침만으로는 부족합니다

표준편차가 크면 거의 모든 것이 겹칩니다. 명문화합니다.
