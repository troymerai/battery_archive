# SCHEMA — findings 레코드 형식

`findings/registry.yaml` 한 레코드의 형식과 **판정 유도 규칙**입니다.

핵심은 하나입니다. **`미조사` 와 `부재확인` 을 구분하는 것.**
안 찾아본 것과 찾아봤는데 없는 것은 다릅니다. 이 둘을 섞으면
"안 찾아봤다" 가 "없다" 로 둔갑합니다.

---

## 레코드

```yaml
- id: LAB-001
  question: "폐기 임계 0.825 의 근거"
  paper:
    status: 미조사
    locus: ""
    value: ""
    searched: ""
    checked_by: ""
  upstream_doc:
    status: 미조사
  code:
    status: 확인
    locus: "BatteryLife/process_scripts/Extract_life_labels.py:124"
    value: "0.825"
    checked_by: CC
  anchors: [EXTRACT_LABELS_ABANDON]
  note: ""
```

세 슬롯을 가집니다.

| 슬롯 | 무엇을 보는가 |
|---|---|
| `paper` | 논문 (본문 · 부록 · 보충자료) |
| `upstream_doc` | 상위 저장소 README · 릴리스 노트 · 이슈 |
| `code` | 상위 저장소 코드 |

`upstream_doc` 은 **보조 근거**입니다. 상위 README 는 논문도 코드도
아니어서, 여기 있는 서술이 논문 근거를 대신하지 못합니다. 표에는 보이되
판정에는 들어가지 않습니다. 판정은 `paper` × `code` 로만 유도합니다.

---

## 슬롯 상태는 5가지다

앞의 3개만 두면 "안 찾아봤다" 가 "없다" 로 둔갑합니다.

| 상태 | 뜻 | 기록 요건 |
|---|---|---|
| `미조사` | 아직 안 찾아봄 | — |
| `확인` | 있음 | `locus` 필수 (§·쪽·파일:행) |
| `부재확인` | 찾아봤고 없음 | **어디를 봤는지** 를 `searched` 에 적음 |
| `조사했으나불명` | 찾아봤고 근거를 못 댐 | `searched` + 왜 불명인지 |
| `구조적불가` | 확인 경로 자체가 없음 | 왜 불가한지 (예: 외부 Excel 미배포) |

`python run.py claims` 가 이 요건을 검사합니다. `확인` 인데 `locus` 가
없거나, `부재확인` 인데 `searched` 가 없으면 위반으로 잡힙니다.

### `searched` 에 무엇을 적는가

"논문 봤음" 은 `searched` 가 아닙니다. 다음 사람이 같은 곳을 다시 뒤지지
않을 만큼 적으십시오.

```yaml
searched: "본문 §3.2, Table 1, 부록 A.1~A.3, 보충자료 없음. 0.825 · 82.5% 로 전문 검색"
```

## 판정 유도

| 논문 슬롯 | 코드 슬롯 | 판정 |
|---|---|---|
| 미조사 | 확인 | **미정** — "코드 전용" 이라 말할 수 없음 |
| 부재확인 | 확인 | 코드전용 |
| 조사했으나불명 | 확인 | **근거불명** — 값은 있으나 출처를 못 댐 |
| 확인 | 확인 · 값 같음 | 일치 |
| 확인 | 확인 · 값 다름 | 불일치 |
| 확인 | 부재확인 | 논문전용(미구현) |
| 아무거나 | 구조적불가 | **확인불가** — 종결 상태. 미해결로 쌓아두지 않음 |

`확인불가` 는 실패가 아니라 **종결된 판정**입니다.
`docs/OPEN_QUESTIONS.md` 의 미해결 목록에 넣지 않고 별도 절에 둡니다.

Farasis · CALB 라벨처럼 외부 자료 미배포로 구조적으로 확인 불가한 항목이
실재합니다. 그런 항목을 계속 미해결로 두면 압력이 걸리고, 압력이 걸리면
그럴듯한 설명을 지어 붙이게 됩니다.

**목표는 불명이 0이 되는 것이 아니라, 불명이 불명으로 남아 있는 것입니다.**
원인 불명 값이 `설명됨` 으로 둔갑하지 않는 것이 이 저장소의 존재 이유입니다.

## `verdict` 는 손으로 쓰지 않는다

`verdict` 필드를 레코드에 적지 마십시오. `verify/render.py` 가 슬롯에서
유도합니다. 적혀 있으면 `python run.py claims` 가 위반으로 잡습니다.

사람이 쓰면 슬롯과 결론이 어긋나도 아무도 모릅니다. 유도하면 슬롯을 고치는
것 말고는 결론을 바꿀 방법이 없습니다.

판정을 바꾸고 싶으면 **슬롯을 고치십시오.**

## YAML 주의

**위치 필드는 항상 따옴표로 감싸십시오.**

```yaml
locus: "Extract_life_labels.py:124"     # 좋음
locus: Extract_life_labels.py:124       # 나쁨 — 파서에 따라 깨집니다
locus: "10:30"                          # 반드시 따옴표. 없으면 시각(sexagesimal)으로 읽힙니다
```

이 저장소는 PyYAML 이 없으면 `verify/_minyaml.py` 로 읽습니다. 다음은
지원하지 않습니다 — 쓰지 마십시오.

- 블록 스칼라 `|` `>`  → 긴 글은 한 줄 `"..."` 로
- 앵커 `&` `*`, 태그 `!`
- 여러 문서 `---`
- flow 매핑 `{a: 1}` (flow 시퀀스 `[a, b]` 는 됩니다)

## 레코드를 언제 추가하는가

씨앗 레코드는 **출발점이지 완성 목록이 아닙니다.**

특히 `META-` 계열은 배포 데이터 재집계(`notebooks/01_pkl_structure.ipynb`)
에서 나온 불일치를 보고 확정합니다. 목록을 미리 다 적으면 재집계에서 나올
것들을 놓칩니다.

```
1. 배포 데이터 재집계     01 노트북이 전 셀의 메타 필드 고유값을 센다
2. 논문 숫자와 대조       Table 1 · Abstract · 부록 A
3. 갈리는 것만 레코드화   META- 목록은 여기서 확정된다
4. 논문 근거 찾기         부록까지. 못 찾으면 `조사했으나불명`
```

id 접두사:

| 접두사 | 무엇 |
|---|---|
| `LAB-` | 라벨 생성 규칙 |
| `DAT-` | 데이터 전처리 · 수식 |
| `META-` | 데이터셋 메타데이터 집계 (셀 수 · 화학계 · 프로토콜 …) |
| `REP-` | 저장소 간 관계 |
| `VER-` | 배포 판본 (v11 / v12) |

## 실패와 실패 아님

| 실패 | 실패 아님 |
|---|---|
| 코드가 안 돌아감 | 배포 라벨과 우리 계산이 다름 → **발견** |
| 값이 다른데 **어느 셀이 어떻게 다른지 못 짚음** | 논문 근거를 못 찾음 → `조사했으나불명` 으로 기록하면 성립 |
| 값에 상태가 안 붙음 (설명 없이 통과) | 확인 경로 자체가 없음 → `구조적불가` 로 기록하면 성립 |
| `미조사` 를 `조사했으나불명` 으로 말함 | |

**"원인 불명이면 안 된다" 를 규칙으로 삼지 않습니다.**
